# AutoTune

多平台内容协作与社区反馈工作台

AutoTune 面向国内外社媒运营，统一整理 X、Facebook、Instagram、Discord、小红书、抖音等平台的内容排期、素材、文案版本、发布记录、互动反馈与基础数据，减少跨平台运营中的重复整理工作。

[体验在线工作台](https://autotune-community-workbench.zbjgrhr.chatgpt.site)（当前为私有站点，仅站点所有者可访问）

## 新版工作台

代码位于 [`web/`](web/)，是无需构建的 HTML、CSS、JavaScript 应用。当前已实现：

| 模块 | 功能 |
| --- | --- |
| 工作总览 | 本周排期、待回复反馈、发布留档、奖励待办与跨平台日历 |
| 内容日历 | 记录选题、活动、文案、素材、语言、负责人、平台、发布时间及状态；按平台筛选并导出待发布清单 |
| 素材资产库 | 为图片、视频和文案登记版本、活动、角色、语言、地区及使用状态，支持检索 |
| 双语文案 | 保存文案版本，检查平台字数、链接格式和项目术语，提示人工审校 |
| 发布归档 | 记录计划与实际发布时间、链接、点赞、评论、分享、浏览量及异常，导出日报 |
| 社区反馈 | 归集评论、私信和社群反馈，标注类型、情绪、活动、紧急度及处理状态，生成摘要 |
| 活动奖励 | 核对 UID、奖品发放与公示状态；新增时提示同活动、同 UID 的重复记录 |
| 数据复盘 | 汇总基础互动、浏览、反馈处理率与问题分布，导出周报 |

页面预置了**演示数据**。新增与修改的数据保存在当前浏览器的 `localStorage` 中，不会自动同步到其他设备或账号。导出的 CSV 可用于进一步制作日报和周报。

### 本地运行

用静态 HTTP 服务打开 `web/` 目录即可，例如：

```bash
npx serve web
```

也可以直接打开 `web/index.html` 查看界面；部分浏览器对本地文件的权限行为可能不同，建议使用 HTTP 服务。

### 当前边界

这是一版可交互的运营流程原型。它**尚未**接入社媒平台 API、实际素材文件存储、跨成员协作后端或 AI 模型服务。发布链接与互动数据由运营人员录入；双语模块目前提供规则检查和版本留存，不能自动生成译文或改写。正式使用前还需要身份权限、持久化数据库、平台授权、术语库与审校流程。

## 早期浏览器扩展

仓库根目录的 `src/`、`packages/core/`、`manifest.config.ts` 和 Vite 配置属于早期“自动回复插件”原型，与新版工作台分开保留，便于追溯。它的构建命令仍为：

```bash
npm install
npm run build
```

构建产物在根目录 `dist/`，可作为 Chrome / Edge Manifest V3 扩展加载。该扩展的自动发送能力不是新版工作台的功能，也不应被理解为已接入新版的社区反馈流程。

## 项目方向

下一步可围绕真实运营流程接入团队数据存储、素材上传、平台发布与评论接口、AI 辅助翻译改写，以及更完整的审批、异常提醒和数据口径管理。
